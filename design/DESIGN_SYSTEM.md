# nestjs-under-load 화면 스타일 가이드

> 상태: 시안 v0.6 (2026-10-07, G01 편집 모델·응답 계약 반영, 처리 방식 5개, 원인 장면·트랜잭션 경계·커서, 한 화면 배치, 저장 경로 = 원장·이력과 한 트랜잭션, 편집 잠금 보유자 종료 두 장면) · 기준 구현: [`mockup.html`](./mockup.html) · 화면 명세: [`../docs/DESIGN.md`](../docs/DESIGN.md) §9.4, §10
>
> 이 문서는 **화면 안의 스타일**만 다룬다. 도트(픽셀) 그래픽, 한글 픽셀 폰트, 제한된 팔레트, 낮은 해상도를 정수 배율로 키우는 방식이 그 내용이다. 레이아웃은 평범한 웹 대시보드다. 기기 모양을 흉내 내는 장식(본체, 경첩, 베젤, 십자키, 버튼 배열)은 쓰지 않는다.

---

## 0. 원칙

1. **장식보다 정보.** 도트는 상태를 빨리 읽게 하려고 쓴다. 볼거리로 쓰지 않는다.
2. **정합성이 먼저.** 어떤 화면이든 숫자는 `정합성 위반 수 → 처리량 → p95 → 실패율` 순서로 놓는다(DESIGN §3-1). 위반 수가 가장 크다.
3. **색 하나로 상태를 전하지 않는다.** 상태 색에는 늘 도트 아이콘이나 글자를 함께 붙인다.
4. **무대는 이벤트로만 움직인다.** 캐릭터는 이벤트 phase가 바뀔 때만 움직인다. 시간이 흐른다는 이유만으로 움직이는 가짜 애니메이션은 넣지 않는다(DESIGN §10.3). 걷기 같은 이동은 **기록된 두 이벤트 사이의 보간**일 뿐이고, 이벤트 없이 상태(락·버전·내용)가 바뀌지 않는다. 그래서 빈 구간을 접어도 장면의 의미는 그대로다. 시안은 가짜 이벤트를 재생하지만 같은 규칙을 따른다.
4-2. **원인을 먼저 보인다.** 결과(덮어씀·409)만이 아니라 원인(두 사람이 같은 버전을 받는 순간)을 핵심 이벤트로 보이고 거기서도 멈출 수 있게 한다(DESIGN §10.3 무대 표현 원칙).
4-1. **실시간이 아니라 기록 재생.** 실제 요청은 수십 ms 안에 끝나서 눈으로 따라갈 수 없다. 무대와 타임라인은 실행이 남긴 이벤트 기록을 느리게 재생한다. 화면 전체(장면, 결과 카드, 서버 속, 타임라인)는 **재생 위치 P 하나의 함수**다. 그래서 앞뒤로 감아도 상태가 어긋나지 않는다. 재생 속도와 실제 시간이 다르다는 사실은 늘 화면에 적는다(§4.8).
5. **정직한 표기.** 화면 푸터에 DESIGN §3.1 기본 문구를 둔다. 인위 개입에는 `주입됨` 배지를 붙이고, 표본을 보여 줄 때는 `대표 N명 표시 / 전체 M명`을 붙인다.

### 1.2 상태 색 (고정, 바꾸지 않는다)

| 상태 | 색 | 아이콘 | 배지 글자색 | 이벤트 phase |
|---|---|---|---|---|
| 정상·커밋 | `--ok` | ✓ check | `--paper` | `committed` |
| 대기 | `--wait` | ⧗ hourglass | `--ink` | `lock_wait`, 풀 대기 |
| 충돌·실패 | `--bad` | ! bang / ✕ cross | `--paper` | `conflict`, `failed`, `custom:lost_update` |
| 재시도 | `--retry` | ↻ retry | `--ink` | `retry` |
| 정보 | `--info` | → arrive / 자물쇠 | `--paper` | `arrived`, `lock_acquired` |
| 중립 | `--sunk` 바탕 + 1px 테두리 | 서류/연필 | `--fg` | `db_read`, `db_write`, `lock_released`, `responded` |

- 처리 방식 태그도 같은 색을 쓴다: 고장(broken)=빨강 ✕, 고침(fixed)=초록 ✓, 절충(tradeoff)=파랑 자물쇠. 절충에 노랑을 쓰지 않는다. 노랑은 "대기"에만 쓴다.
- 대비: 흰 글자 배지(`ok`, `bad`, `info`)는 `--paper`와 대비 4.5:1 안팎이 되게 어둡게 잡았다. 노랑·주황 배지는 검은 글자(`--ink`)를 쓴다.
- 캐릭터·이름표 색(`--slate`, `--wood`, `--ink`, `--mist`)에는 상태 색을 쓰지 않는다. 누가 누구인지와 무슨 상태인지가 섞이지 않게 하려는 것이다.

## 3. 간격·배율

### 3.1 간격
- 4px 그리드: `--s1 4` · `--s2 8` · `--s3 12` · `--s4 16` · `--s5 20` · `--s6 24` · `--s8 32`.
- 카드 안쪽 여백은 12px, 카드 사이 간격은 16px, 휴대폰 좌우 여백은 16px다.
- 모서리는 둥글리지 않는다. 대신 **2px 계단 모서리**를 쓴다: `clip-path: var(--notch)`. 카드, 버튼, 배지, 칩에 같은 값을 쓴다.

### 3.2 무대 해상도와 정수 배율
- 논리 해상도는 **256×192**다. 모든 스프라이트와 좌표는 이 격자 위에 둔다.
- 확대는 **기기 픽셀 기준 정수배**로만 한다:
  `n = floor(가용폭 × devicePixelRatio / 256)`, CSS 배율 `K = n / DPR`(최대 4×DPR).
  이렇게 하면 논리 1px이 늘 기기 픽셀 n개로 그려진다. DPR이 2인 화면에서는 CSS 배율이 1.5처럼 보여도 기기 픽셀로는 3배라서 번지지 않는다.
- 캔버스에는 `image-rendering: pixelated`(대체 `crisp-edges`)를 주고 `imageSmoothingEnabled = false`로 둔다.
- ≥1120px에서는 높이로도 제한한다: `nh = floor((뷰포트 높이 − 무대 위쪽 − 하단 줄 30 − 재생 바 − 트랜잭션 띠 요약 58 − 4) × DPR / 192)`, `n = max(min(DPR, n), min(n, nh))`.
  - **아래 시트 높이는 넣지 않는다.** 시트는 배율 < 2일 때만 뜨므로, 넣으면 "시트가 떠서 배율이 줄고 → 배율이 작아 시트가 계속 뜨는" 순환으로 ×1에 갇힌다.
  - 하단 줄(30px)과 트랜잭션 띠 요약(58px)은 배율과 무관한 고정 높이로 두고 늘 미리 비워 둔다. 그래야 자동 멈춤에서 요약이 떠도 배율이 바뀌지 않고, 창을 줄였다 늘리면 배율이 돌아온다.
  - 확인(2026-10-07): 1440×900·1440×790에서 DPR 1·2 모두 ×2(DPR 2는 기기 픽셀 4배), 자동 멈춤 → 520px로 줄임(×1·시트) → 원래 높이로 되돌림 → ×2 복귀.
- 남는 폭은 `--stage-mat` 레터박스로 채운다. 늘려서 채우지 않는다.
- 글자는 캔버스에 그리지 않는다. 말풍선·이름표·팝업은 캔버스 위 HTML 레이어에 두고, 위치는 `논리좌표 × K`로 맞춘다. 그래야 배율과 상관없이 글자가 또렷하다. K<2이면 10px(Galmuri9)로 줄인다.

### 3.3 반응형 배치 (기준: mockup.html)
| 폭 | 배치 |
|---|---|
| ≥1120px | 설정(전체 폭) / 왼쪽 열: 무대 → (자동 멈춤 때) 트랜잭션 띠 요약 → 재생 바 → 타임라인(접이식) · 오른쪽 열: 결과(한 줄 4칸) → `코드 | 서버 속`. **무대 + 재생 바 + 코드 패널이 한 뷰포트(100vh) 안에** 들어온다: 무대 배율은 폭과 남은 높이 둘 다로 제한하고(§3.2), 코드 본문 높이는 남은 화면에 맞춘다. 세로를 아끼려고 설정은 라벨을 왼쪽에 붙인 32px 두 줄(편집 시간 힌트는 `title`로), 재생 바는 `빈 구간 빨리 감기` 토글을 시계 줄로 옮겨 세 줄로 둔다. 비교를 켜도 오른쪽 열에 그대로 둔다(위아래 분할) |
| 760–1119px | 설정 → 무대 → 재생 바(**sticky**, 화면 위에 붙음) → 결과(한 줄 4칸) → 코드/서버 속 → 타임라인 |
| <760px | 무대 → 재생 바 → 결과 → 설정(한 줄 요약으로 접힘) → 코드/서버 속 → 타임라인. 자동 멈춤 설명은 무대 밖 아래 시트로, 코드는 강조 줄 ±5줄 미니 보기(스크롤 트랩 없음, "전체 코드 보기" 버튼) |

- 가로 스크롤이 생기면 안 된다. 긴 SQL·설명은 한 줄 말줄임으로 자르고 원문은 `title`에 넣는다.
- 휴대폰 폭에서는 설정을 `설정 · 덮어쓰기 · 2명 · 일정 ▾` 한 줄로 접고, 펼치면 처리 방식 세그먼트를 세로 목록으로, 실행 버튼을 전체 폭으로 바꾼다. 버튼 글자는 `word-break: keep-all`. 기록이 없을 때는 무대 가운데 CTA가 같은 `실행하기`를 부른다(재생 바는 실행하지 않는다, §4.8).
- 어느 폭에서든 무대 HUD에 정합성 배지(`✕ 위반 N` / `✓ 정합성 OK`)가 있다. 결과 카드가 화면 밖으로 밀려도 위반 여부는 무대에서 바로 보인다.

## 4. 컴포넌트

### 4.1 패널(카드)
- `2px solid var(--edge)` 테두리, 계단 모서리, `--panel` 바탕을 쓴다. 그림자는 넣지 않는다.
- 머리줄(`.panel__h`): 제목(Galmuri11 Bold 12px) 왼쪽, 메타(10px `--dim`) 오른쪽, 아래에 2px `--line`.
- 카드 안 구분선은 `--line` 2px(구획)이나 1px 점선(목록 행)으로 긋는다.

### 4.2 상단 바
- 브랜드 + 화면 탭(시나리오·실행·비교·기록·지표) + 도구(**가짜 데이터 고지** · `단축키 ?` · 테마)로 구성한다.
- 고지 `시안용 가짜 데이터 · 가짜 이벤트 재생 · 서버 연결 없음`은 12px, 노랑 2px 테두리 칩으로 늘 보이게 둔다(푸터에만 두지 않는다).
- 단축키 목록은 `?` 오버레이(`role=dialog`, Esc로 닫고 포커스 복귀)에 둔다. 푸터에 단축키 줄을 두지 않는다.
- 탭이 선택되면 `--sel-bg`/`--sel-fg`로 반전하고 `aria-current="page"`를 붙인다.

### 4.3 설정 컨트롤 바
- **시나리오**: 이 시안은 범용 팩 `G01 같은 문서 동시 수정` 하나다(배지 + 이름, 선택 없음). 세무 팩 T01은 "수정 vs 승인 동시 도착"을 다루는 다른 장면이라 여기서 고르지 않는다(툴팁으로 안내).
- **드롭다운**(비교 대상 등): 기본 `<select>`에 `appearance: none`을 주고, 2px 테두리와 인라인 SVG 도트 화살표를 단다.
- **세그먼트 버튼**(처리 방식·인원·부하 모양): `role="radiogroup"` 안에 `role="radio"` 버튼을 둔다. 선택된 항목은 반전한다. 방향키 ←→로 값을 옮기고, 포커스는 선택된 항목 하나만 받는다(roving tabindex).
  - 처리 방식 5개: `고장 덮어쓰기(naive-overwrite)` · `고장 맹목 재시도(blind-retry)` · `고침 버전 감지(optimistic-version)` · `절충 필드 병합(field-merge)` · `절충 편집 잠금(edit-lease)`. 첫 실행 기본값은 **덮어쓰기**.
  - 준비 안 된 항목(field-merge)은 `aria-disabled` + 빗금 바탕 + `준비 중` 글자. 클릭·방향키·`S` 순환에서 건너뛴다.
  - 처리 방식 항목에는 상태 태그 배지(고장/고침/절충)를 앞에 붙인다.
  - 부하 모양 항목에는 6칸 막대로 그린 도트 모양 글리프를 앞에 붙인다.
- **편집 시간(사람) 슬라이더**: `압축 ↔ 2초 ↔ 30초 ↔ 5분`. 편집 잠금에서만 결과(잠금 대기 p95, 처리량)가 달라지고, 다른 방식에서는 흐리게 두고 "다른 방식은 편집 중 아무것도 잡지 않는다"를 힌트로 쓴다. 무대의 편집 구간은 길이와 상관없이 같은 길이로 압축해 그린다.
- **예측 입력**(선택): `예측: 위반 몇 건?` 숫자 한 칸. 결과 카드에 `예측 N · 지금/실제 M (✓ 적중 / ✕ 빗나감)` 배지로 나란히 보인다(DESIGN §10.3 실행 전 예측).
- **용어**: `실행하기`(기록 만들기) / `재생`·`계속`·`다시 보기`(기록 재생) / `실행 중단`(기록 만드는 중에만 켜짐, 재생 중에는 비활성). 일시정지는 재생 바에서 한다.
- **실행 진입점은 `실행하기` 하나**(설정의 버튼 · `Enter` · 기록이 없을 때 무대 CTA가 모두 같은 동작). 재생 바의 큰 버튼은 기록이 없으면 `재생`으로 비활성이고 `Space`도 아무것도 하지 않는다.
- **실행 버튼**: `--ok` 바탕, 재생 아이콘, `Enter` 표시. **실행 중단 버튼**: 패널 바탕, 정지 아이콘, `Esc` 표시.
- 누른 상태는 아래쪽 3px 안쪽 그림자를 1px로 줄이고 1px 내려서 표현한다(도트식 눌림).

### 4.4 결과 카드
- 위반 수는 **재생 위치까지**의 누적, 처리량·p95·실패율은 **기록 전체 요약**(재생 위치와 무관)이라고 라벨에 적는다(`처리량 · 전체`).
- 넓은 화면(≥760)은 한 줄 4칸(위반 36px + 3칸 24px), 휴대폰은 위반 칸 전체 폭 + 3칸.
- 첫 칸(`--sunk`): **정합성 위반 수** 48px Bold(넓은 화면 36px). 위반이 있으면 `--bad-fg`와 ✕, 없으면 `--ok-fg`와 ✓를 쓴다. 그 옆에 판정 배지(`빠르지만 틀림 · 순위 제외` / `정합성 통과`)와 불변식 설명을 둔다.
- 다음 줄 3칸: 처리량(req/s), p95(ms, "어떤 처리량에서·n=표본"을 함께), 실패율(%, `409 n · 423 n · 재시도 n`을 함께 — `title`에 전체 문장). 24px Bold. 보조문은 말줄임으로 자르지 않고 줄바꿈한다.
- 불변식 보조문은 원장 기준으로 쓴다: 덮어쓰기 `원장엔 커밋된 토큰이 최종 이력엔 없음 · 응답은 전부 200`, 맹목 재시도 `409 뒤 맹목 재시도가 앞사람 토큰을 이력에서 지움`, 그 밖 `원장의 성공 수정 토큰 = 최종 이력 (일치)`. 원장·이력은 저장과 같은 트랜잭션에서 커밋되므로(§4.10) "원장에 있는데 이력에 없다"가 곧 잃어버린 수정이다.
- 위반이 새로 생기면 첫 칸을 빨간 바탕으로 두 번 계단식 깜박임(`steps(2)`) 처리하고, 무대 HUD 위반 배지를 0.3초 계단식으로 키웠다 돌린다(펄스).
- 편집 잠금의 p95 자리는 `잠금 대기 p95`로 바꾸고 편집 시간에 따라 ms/s/분으로 표기한다.
- 맨 아래에 "로컬 단일 머신 · 상대 비교용" 한 줄을 둔다.

### 4.6 서버 속 패널 (화면 4 축약)
- `코드 | 서버 속` 탭 패널의 두 번째 탭이다. 위에 항상 `샘플: 대표 N명분`을 붙인다(DESIGN §9.4).
- **격리 수준**: `READ COMMITTED` 배지(용어 툴팁) + "처리 방식이 바꾸지 않음". 아래 `왜? 격리 수준을 올리면 덮어쓰기가 막힐까` 펼치기: 읽기(자동 커밋 SELECT)와 저장(begin → UPDATE → 원장·이력 INSERT → commit)은 서로 다른 트랜잭션이고 그 사이에 사람 편집 시간이 있어 SERIALIZABLE로도 못 막는다. 대비로 "한 트랜잭션 안이었다면 SERIALIZABLE은 늦은 쪽을 40001로 중단"을 한 줄 둔다.
- **락·잠금 트리**: 처리 방식마다 무엇을 보여 주는지가 다르다. 서로 섞지 않는다.
  - 덮어쓰기·맹목 재시도·버전 감지: **DB 행 락**만. 보유자(`UPDATE 실행됨 · 원장·이력 INSERT 뒤 commit 전`) 아래 `└` 대기자(`B 커밋 → WHERE 재평가 → 0행`). 행 락이 없을 때는 "편집 중엔 락이 없다"를 한 줄로.
  - 편집 잠금: ① 편집 잠금(DB 칼럼 `locked_by`·`lease_until`) 보유자 또는 `만료`, 보유자가 떠났으면 `└ 이탈 · release 없음 → TTL 만료로만 회수`, 멈췄으면 `└ 멈춤 · 서버는 살아 있는지 모름` ② **문 밖 · 클라이언트 쪽 재시도(서버 큐 아님 · 순서 보장 없음)** — 423을 받은 사람과 `Retry-After 뒤 다시 노크 · 커넥션 없음`, 잠금을 잃은 줄 모르는 멈춘 옛 보유자 ③ DB 행 락: "acquire·release는 한 문장(자동 커밋), save는 원장·이력 INSERT 뒤 commit까지 — 모두 ms 단위". "대기"를 서버가 줄 세우는 것처럼 그리지 않는다.
- **커넥션 풀**: 10칸. 사용 중 `--info`, 행 락 대기 중인 세션은 노랑 빗금. 오른쪽에 `n/10 사용 · 대표 a + 다른 문서 b · 풀 대기 0`.
- **현재 SQL**: 어두운 블록(고정폭 11px). 키워드 파랑, 경합 핵심 조건(`"version" = $5`, `"locked_by" = $4`, `"fence" = $5`, `"lease_until" > clock_timestamp()`)은 노랑. 파라미터는 `$n`.
- **DB 세션 (pg_stat_activity 샘플)**: HTTP 요청 목록이 아니라 DB 세션이다. 행마다 칩 + pid · state 배지(`active` / `active · Lock` = 행 락 대기) · 쿼리. 편집 중인 사람, 423을 받고 다시 노크하려는 사람은 세션이 없다는 것을 아래 한 줄로 적는다. 세션이 없으면 "지금은 아무도 DB에 있지 않다".
- **이벤트 루프 지연**: 24칸 도트 막대 스파크라인. 임계값을 넘은 칸은 노랑.
- 시계열은 넣지 않는다. 시계열은 Grafana(화면 5)가 맡는다.

### 4.7 이벤트 타임라인
- 머리줄의 제목이 접기 버튼이다(`aria-expanded`). 구성: 도구 줄(`핵심만 | 전체` + 종류 필터 칩) → **범례(`#legend`)** → 레인 → 행 목록 → 기준 안내 한 줄. 표시 규칙은 §4.9.
- **레인 = 요청별 트랜잭션 경계 띠**(16px). 대표 actor마다 한 줄.
  | 띠 | 모양 | 뜻 |
  |---|---|---|
  | 읽기 | `--slate` 짧은 막대 | 자동 커밋 SELECT(트랜잭션 하나로 끝) |
  | 편집 | `--mist` 빗금 + 1px 테두리 | 사람 시간(압축). DB 세션 없음 |
  | 저장 begin–commit | `--info` 2px 테두리 상자(rollback이면 `--bad`) | **모든 저장 경로**(덮어쓰기 포함): `em.transactional` = begin → UPDATE → 원장·이력 INSERT → commit. lockVersion 메모리 비교에서 걸린 409도 begin … SELECT … rollback 짧은 빨강 상자 |
  | 자동 커밋 UPDATE | `--info`로 채운 막대 | 편집 잠금의 acquire·release(조건부 UPDATE 한 문장). 쓰기라서 읽기(`--slate`)와 다른 색 |
  | 행 락 대기 | 노랑 빗금 가는 띠(트랜잭션 상자 안) | 같은 행의 앞 트랜잭션 commit 대기 |
  | 편집 잠금 보유 | 위쪽 3px `--info` 선 | acquire ~ release/만료 |
  커밋은 초록, 409·위반·보유자 이탈·멈춤은 빨강, 423은 노랑 2px 세로 표시. 각 띠에 `title`로 뜻을 단다. 범례(`#legend`)는 이 표와 같은 이름·색을 쓴다.
- **행**: `+실제 ms` · 칩 · phase 배지(`×N`) · 설명(12px).

### 4.8 기록 재생 컨트롤 (재생 바)

실행하면 기록을 만든다(실서비스에서는 WS로 받은 이벤트를 쌓은 것). 그다음 그 기록을 재생한다. 재생 바는 무대 바로 아래 붙은 패널이고, 760–1119px에서는 sticky로 화면 위에 붙는다.

| 요소 | 모양·동작 |
|---|---|
| 처음 / 이전 단계 / 재생 / 다음 단계 | 32px 아이콘 버튼 3개 + 반전색 큰 버튼. 큰 버튼 글자는 상황마다: `재생`(기록 없음 — **비활성**, 실행은 `실행하기`로만) · `재생` · `일시정지` · 자동 멈춤 뒤 **`▶ 계속`** · 끝나면 `다시 보기`. 단계는 **타임라인에 보이는 행** 단위이고, 행의 마지막 이벤트 시각에 선다 |
| 속도 | 세그먼트 `아주 느리게 · 느리게 · 보통 · 빠르게`. 툴팁은 `실제의 1/400 속도`처럼 **1/N 표기만**(화면 안에 `0.25×` 같은 표기를 쓰지 않는다). 기본 `느리게` |
| 기준 문장 | 시계 줄 오른쪽에 한 문장: `실제의 1/160 속도로 재생 · 빈 구간 접음`. 기록 끝에서는 같은 자리에 요약 `4라운드 중 위반 3건 · 409 n · 423 n`(굵게) |
| 자동 멈춤 | 토글 + 체크박스 `원인에서도`(기본 ON). 멈추는 곳: 원인(두 번째 사람이 **같은 버전**을 받음), 409, 잃어버린 수정, 행 락 대기, 첫 423, 보유자 이탈, 보유자 멈춤, TTL 만료. 같은 종류·같은 설명(409라면 실패 지점과 "재시도도 409"까지 같을 때)이 무대 1.4초 안에 이어지면 한 번만. **멈춤 위치 = 그 이벤트 시각 그대로**라서 시계 · 코드 상자 · 설명이 한 장면에 시각 하나를 보인다 |
| 빈 구간 빨리 감기 | 토글, 기본 ON(`F`). 걷기·편집(사람 시간) 같은 이벤트 없는 구간을 접는다. 이동은 이벤트 사이 보간이라 접어도 상태가 달라지지 않는다 |
| 스크러버 | 라운드 경계 `R1…R4`, 핵심 눈금(빨강=409·위반·보유자 이탈·멈춤, 노랑=행 락 대기·첫 423·만료, 주황=재시도, 파랑=같은 버전 수신). 접히는 구간은 빗금. `<input type=range>` |
| 시계 | 기본 표시는 `R1/4 · +116.0ms / 156.0ms`만. 전체 경과·`실제의 1/N 속도`·"편집 구간은 압축" 같은 나머지는 툴팁 |
| 무대 하단 줄 | `■ 실제 162.5ms 라운드를 1/160 속도로 멈춤` / 빈 구간에서는 `▶▶ 빈 구간 빨리 감기 · 실제 20.5ms를 0.3초로` |

**빈 구간 압축(빨리 감기)**
- 이벤트마다 앞 100 · 뒤 480 무대ms 창을 만들고, 창의 여집합이 "빈 구간"이다. 선택 속도로 0.3초를 넘는 공백만 0.3초(벽시계)로 접는다.
- 압축은 P가 흐르는 속도만 바꾼다. 장면 계산이나 이벤트 시각은 바뀌지 않는다.

**자동 멈춤 강조**
- 무대 전체를 `rgba(16,18,24,.42)`로 어둡게 하고 대상 주위 44×44 논리px만 밝게 남긴다(흰 2px 틀 + 노란 꺾쇠). 원형 스포트라이트는 쓰지 않는다.
- 설명 말풍선: `[■ 자동 멈춤]` 배지 + **굵은 한 줄 요약** + 보충 + `Space 계속 · → 다음 단계` + **버튼 `▶ 계속`**. 760px 미만이거나 배율이 2 미만이면 무대 안이 아니라 **무대 아래 시트**에 같은 내용을 띄운다(무대를 가리지 않게).
- **트랜잭션 띠 요약**: 자동 멈춤 동안 무대 바로 아래(시트 아래, 하단 줄 위)에 고정 높이 58px 띠를 띄운다. 머리줄 `트랜잭션 띠 · R2 시작 → +93.5ms · B: 읽기(자동 커밋) → 편집(사람 시간) → begin…commit`, 그 아래 두 줄 = 멈춘 사람 + 관련된 사람(행 락·잠금 보유자, 덮어쓴 사람)의 레인을 라운드 시작부터 지금까지로 늘려 그린다(멈춘 사람 줄은 1px 테두리). 타임라인이 첫 화면 밖이어도 설명과 트랜잭션 경계를 같이 본다. 높이는 배율 계산이 미리 비워 둔다(§3.2).
  - 원인: "**B도 같은 버전(v7)을 받았다 — 아직 아무도 저장 전** A는 +37.5ms, B는 +46.0ms에 읽었다."
  - 잃어버린 수정: "**B가 A의 수정을 덮어씀** — B는 +46.0ms에 읽었다 — A가 저장한 +93.5ms보다 먼저." 이때 타임라인에서 B의 읽기 행을 노랑(원인)으로 함께 강조한다.
  - 맹목 재시도: "**A가 버전만 바꿔 같은 본문을 다시 보냄 → B의 수정이 사라짐**". 409를 받은 사람마다 **그 순간의 currentVersion을 따로 기억**하고, 재시도는 클라이언트 코드의 `if` 한 번 그대로 그 값으로 한 번만 PUT한다. 2명이면 재시도가 통과해 잃어버린 수정 1건. 3명 이상이면 먼저 재시도한 사람이 통과(잃어버린 수정 1건)하고, 같은 값을 기억한 나머지는 그 사이 버전이 올라 **다시 409로 실패해 끝난다** — "**C의 재시도도 409 — 여기서 실패로 끝남**"(본인은 실패를 안다, 저장 안 됨).
  - 409(메모리 비교) / 409(WHERE 재평가 0행) / 409(재시도도 409) / 409(lease_lost)는 서로 다른 문장으로 설명한다. lease_lost는 "**깨어난 A의 늦은 저장이 409 (lease_lost)**" + fence 조건 + "currentVersion은 새 보유자의 acquire(+1)까지 반영된 값".
  - 보유자 이탈: "**잠금을 쥔 A가 떠났다 — release를 보내지 않았다**"(TTL 만료로만 회수). 보유자 멈춤: "**잠금을 쥔 A의 클라이언트가 멈췄다 (GC·네트워크 단절)**"(fence를 든 채, 깨어나 늦게 저장하면 fence로 거른다).
  - 423: "**B는 423을 받고 문 밖으로** — 서버는 줄을 세우지 않는다. Retry-After 뒤 다시 노크, 순서 보장 없음, 커넥션 없음."

**키보드:** `?` 오버레이에 모은다. `Space` 재생/일시정지/계속 · `→`/`←` 단계 · `Home` 처음 · `1`–`4` 속도 · `A` 자동 멈춤 · `F` 빈 구간 · `C` 코드 비교 · `Enter` 실행하기 · `Esc` 실행 중단/오버레이 닫기 · `S` 처리 방식 · `T` 테마. 입력 요소에 포커스가 있으면 전역 단축키를 받지 않는다.

**구현 규칙**
- 재생 위치 P는 무대 ms 단위다(실제 ms × 40). 장면은 `sceneAt(P)`가 라운드 시작부터 이벤트를 접어서(fold) 만든다. 프레임마다 누적하는 물리 상태를 두지 않는다.
- 결과 카드의 위반 수는 이벤트마다 붙여 둔 누적 카운터를 이진 탐색으로 읽는다. 처리량·p95·실패율은 기록을 만들 때 한 번 계산한 요약이다.

### 4.9 타임라인 가독성 규칙

- **기본은 "핵심만"**: 읽기·버전 받기(원인), 락·잠금(행 락 대기·잠금 획득·423·해제·보유자 이탈·멈춤·만료), 409, 재시도, 커밋, 잃어버린 수정. `전체`로 요청·응답·편집·쓰기까지 펼친다.
- **종류 필터**: 켜진 칩은 상태 색 배지, 꺼진 칩은 투명 바탕 + 1px 테두리 + 취소선. "핵심만"에서 볼 수 없는 종류는 비활성.
- **묶기 ×N**: 같은 라운드, 같은 종류, 무대 1.4초 안. 단 **핵심 종류는 같은 사람끼리만 묶는다**(A 커밋 / B 커밋이 순서대로 따로 보이게). 원인 읽기(두 번째 사람)는 묶지 않는다.
- **행마다 실제 경과 시간**: 라운드 시작부터의 실제 ms. 편집 구간은 압축해서 그린다는 것과, 이동은 이벤트 사이 보간이라는 것을 패널 아래 한 줄로 적는다.
- **현재 위치**: `is-now`(파랑 14% + 왼쪽 3px). **원인 행**: `is-cause`(노랑 16% + 왼쪽 3px). 아직 안 온 행은 40% 투명. 목록은 최대 236px 안에서만 스크롤한다.
- 행을 누르면 그 시점으로 이동하고 일시정지한다.

**글꼴과 문법 색**
- 코드 본문은 일반 고정폭 글꼴 12px/18px(휴대폰 11px). 한글 주석만 `GalmuriMono11`. 문법 색은 키워드=`--info`, 문자열·데코레이터=`--wood`, 타입=굵게, 주석=`--dim` 네 가지. 상태 색은 강조와 diff 전용.

**백엔드 정확성 (G01 편집 모델·응답 계약)**
- 편집 모델: 문서 전체 교체(PUT). 클라이언트는 화면을 열 때 받은 `version`을 **요청 본문**으로 돌려준다(If-Match 헤더는 쓰지 않는다 — 412/428 헤더 의미론을 따로 구현하지 않기 위해).
- **원장·이력은 저장과 같은 트랜잭션**: 모든 저장 경로(덮어쓰기·버전 감지·편집 잠금 save)는 `em.fork().transactional(async (em) => { … })` 안에서 UPDATE 뒤 `recordEdit(em, …)`로 원장(`insert into "edit_ledger" … txid_current()`)과 이력(`insert into "document_revision"`)을 넣고 commit한다. 실패(409)는 예외라 rollback되어 원장이 남지 않는다. 그래서 "원장 성공 행 = 서버가 성공 처리한 수정"이고, lost update = 원장엔 있는데 최종 이력(마지막 revision의 토큰 목록)엔 없는 토큰이다. 화면의 트랜잭션 띠·SQL 상자·설명은 모두 `begin … commit`(또는 `rollback`)으로 그린다. 자동 커밋 한 문장은 읽기 SELECT와 편집 잠금의 acquire·release뿐이다.
- 버전 감지: `transactional` 안에서 `findOneOrFail(Document, id, { lockMode: LockMode.OPTIMISTIC, lockVersion: dto.version })` → `assign` → `flush` → `recordEdit`. 트랜잭션은 원장을 같이 쓰려고 연 것이고 lockVersion 자체는 트랜잭션이 필요 없다. 실패 지점이 두 곳이다: ① lockVersion **메모리 비교**(락 SQL 아님, UPDATE 없이 rollback. `undefined`면 검사 생략 → 컨트롤러가 **version 누락은 428, number가 아니면 400**으로 거절하고 number로 변환) ② flush의 `UPDATE … WHERE version = ?` 0행 → rollback. 실제 동시성 보장은 ②다. 둘 다 `409 { reason: 'version_mismatch', currentVersion, current }`(트랜잭션 밖에서 현재본 재조회).
- 동시 UPDATE: 두 PUT이 거의 동시에 ①을 통과하면, 두 번째 UPDATE는 행 락을 기다렸다가 앞 트랜잭션(원장 INSERT 포함) commit 뒤 최신 행으로 WHERE를 재평가(READ COMMITTED, EvalPlanQual)해 0행이 된다. 무대·서버 속에 "행 락 대기 → 재검사 → 0행 → rollback"으로 보인다.
- 덮어쓰기: `transactional` 안에서 `em.nativeUpdate(Document, { id }, { body, tokens, editCount: raw('edit_count + 1') })` → `recordEdit`. **원장과 한 트랜잭션이어도 버전 조건 없이 쓰는 경로다 — 버전 칼럼은 올라가지만(7.1.4는 `"version" = "version" + 1`을 자동으로 붙인다) 아무도 비교하지 않는다.** 이런 경로가 하나라도 있으면 낙관 락 전체가 무력해진다.
- 맹목 재시도(고장): 409 본문의 `currentVersion`만 꺼내 같은 body로 **한 번**(`if`) 다시 PUT. 각자 409 때 받은 값을 쓰므로, 그 값이 아직 현재면 통과해 앞사람 수정이 사라지고(위반 +1), 그 사이 더 올랐으면 다시 409로 실패해 끝난다(§4.8). 올바른 재시도는 "다시 GET → 내 변경을 최신본에 다시 적용(병합·사용자 결정) → 새 버전으로 PUT".
- 편집 잠금: acquire는 조건부 UPDATE 한 번(자동 커밋, 비었거나·내 것이거나·만료된 잠금), 시각은 **DB 시계 `clock_timestamp()`**(`now()`는 트랜잭션 시작 시각이라 쓰지 않음), `fence = fence + 1`. 실패하면 **423**(WebDAV 코드를 일부러 빌려 씀) + `Retry-After` — 서버 큐 없음, 클라이언트 폴링, 순서 보장 없음. save는 `transactional` 안에서 `WHERE id AND locked_by AND fence AND lease_until > clock_timestamp()` 조건부 UPDATE → `recordEdit` → commit, 0행이면 같은 트랜잭션에서 재조회해 `409 lease_lost`(보유자·fence 다름) / `409 lease_expired`(예외라 rollback). release도 **`WHERE id = ? AND locked_by = ? AND fence = ?`**(잠금을 잃은 옛 세션이 새 보유자의 잠금을 풀지 못하게).
- 편집 잠금의 버전: 버전 칼럼이 매핑돼 있어 acquire·save·release가 각각 `version + 1` → **한 차례에 +3**. 그래서 같은 문서를 낙관 락으로 고치는 클라이언트는 내용이 안 바뀌어도 잠금 조작만으로 409를 받을 수 있다.
- 보유자가 끝나는 두 장면(서버 인스턴스와 무관 — 잠금은 DB 칼럼이라 서버를 죽여도 그대로다):
  ① **클라이언트 이탈**(탭 닫기 등) → release(`DELETE /lease`)가 오지 않음 → 다른 사람은 423 → TTL 만료 → 다음 노크가 회수(fence +1).
  ② **같은 클라이언트가 멈췄다 깨어남**(GC·네트워크 단절) → 그사이 TTL 만료·다른 사람이 회수 → 깨어난 A가 옛 fence로 늦게 저장 → `locked_by`·`fence` 불일치 0행 → `409 lease_lost`. 이 409의 `currentVersion`은 서비스가 409 직전에 재조회하므로 **새 보유자의 acquire(+1)까지 반영된 값**이다.
- 응답 계약: 저장 실패는 모두 409(`reason`: version_mismatch | lease_lost | lease_expired, `currentVersion`·현재 내용 포함), 423은 acquire 거절에만, version 누락은 428, 타입 오류는 400.
- 코드 확인: 서버 코드(엔티티·dto·record-edit 포함)는 `@mikro-orm/core·postgresql·decorators 7.1.4`, `@nestjs/common 11.1.27`, TypeScript 5.9.3 `strict` + `experimentalDecorators`로 `tsc --noEmit` 통과를 확인했다(2026-10-07, `em.transactional`·`em.insert`·`raw` 시그니처 포함). SQL 표기(`select "d0".* … limit $2`, `insert into "edit_ledger" (…) … returning "id"`, `returning "version"`, 별칭 규칙)는 같은 버전 드라이버가 만든 문장을 연결 없이 가로채 맞췄다. 클라이언트 줄은 k6 의사 코드다. 버전이 바뀌면 다시 확인한다.

**이벤트 → 코드 매핑(codeRef)**
- 코드 원문 줄 끝에 `⟦tag⟧`를 달고 파싱할 때 떼어 낸다. `codeMap(처리 방식, 이벤트) → { tag, also, sql[], note, tone }` 한 함수가 줄·SQL·설명을 함께 만든다(서로 모순 없게). 실서비스에서는 이벤트의 `attrs.codeRef`와 SQL 샘플 이벤트(DESIGN §9.1)로 채운다.

- 칩(actor 이름표)은 `A/B/C/D` 글자와 actor 색으로 만든다. 타임라인, 트리, SQL, 무대 이름표에서 같은 색을 쓴다.

### 4.12 도트 아이콘
- 8×8 비트맵 문자열 배열(`'#'` = 채움)을 한 번만 정의한다. 이것을 UI에서는 `<svg viewBox="0 0 8 8" shape-rendering="crispEdges" fill="currentColor">`로, 캔버스에서는 `fillRect`로 그린다. 한 원본을 두 곳에서 쓰는 방식이다.
- 현재 세트: arrive, wait, bang, retry, check, cross, lock, unlock, read, write, play, stop, out. (무대 감정 표시는 check·bang·retry·wait·write(편집 중)·stop(보유자 멈춤))

## 5. 도트 스프라이트 규칙

- **격자**: 256×192 논리 좌표, 1 논리 px = 1 칸. 좌표는 정수로 반올림한 뒤 그린다(`Math.round`). 반 픽셀은 쓰지 않는다.
- **정의 방식**: 문자열 배열과 문자 → 팔레트 매핑으로 정의한다(예: `k`=ink, `S`=정장색 치환). 외부 이미지·스프라이트시트를 쓰지 않는다.
- **캐릭터**: 12×18(머리·몸 14줄 + 다리 4줄). 다리 프레임은 stand / a / b 3장이고, 걸을 때 140ms마다 바꾸며 1px 위아래로 흔든다. 좌우는 가로 뒤집기로 처리한다. 발밑에 8×2 `--mist` 그림자를 둔다.
- **사물**: 서류 14×16(파란 머리줄 + 본문 줄), 자물쇠 7×8, 들고 있는 사본 7×7, 감정 표시는 12×12 말풍선 안에 8×8 아이콘을 넣는다.
- **외곽선**: 밝은 바닥 위에서도 보이게 사물에는 `--ink` 1px 외곽선을 두른다.
- **깊이**: 그리는 순서는 y좌표 오름차순이다.
- **움직임**: 이동 속도는 90 논리px/s(무대 시간 기준, 코드 `PX_PER_MS = 0.09`)다. 튕김(409)은 사인 곡선으로 10px 밀렸다 돌아오고, 쓰기는 4px 들썩임으로 표현한다. 날아가는 종이만 반투명을 쓴다(사라지는 표현). 그 밖에는 알파를 쓰지 않는다.
- **장면 사전**(shared-document, DESIGN §10.3):

| phase | 장면 동작 |
|---|---|
| `arrived` | 출입구(좌/우)에서 책상 자리로 걸어감. 편집 잠금의 acquire는 책상 앞 노크 자리로. 이미 자리에 있으면(PUT) 움직이지 않음 |
| `db_read` | 사본을 듦 + 발밑 `v7` 표지(받은 버전, §4.5). 두 번째 사람이 같은 버전을 받는 순간이 원인 장면 |
| `editing` | 연필 감정 표시(편집 중 · 사람 시간). DB 문서는 바뀌지 않는다 |
| `db_write` | 들썩임 + 서류 위에 펜 움직임 |
| `lock_wait` | 책상 앞에서 ⧗ + 노란 말풍선 "B 커밋 기다리는 중 (행 락)" |
| `committed` | 사본 내려놓음 + ✓, 서류 들썩임, DB 문서 버전 표지 갱신 |
| `custom:lost_update` | 앞사람 수정이 종이째 날아가며 사라짐 + "잃어버린 수정 +1" 빨강 팝업 + 결과 카드 깜박임 + HUD 배지 펄스 |
| `conflict` | ! + "409 · 먼저 고쳐졌어요 (v8)" / 맹목 재시도의 두 번째 409는 "409 · 또 거절 (v9) · 포기" / "409 · 잠금을 잃었어요" 말풍선 + 튕김 |
| `retry` | ↻. 편집 잠금에서는 문 밖에서 노크 자리로 다시 걸어감 |
| `lock_acquired` | 서류에 자물쇠(보유자 색 띠) + 책상 자리로(멈춘 옛 보유자가 서 있으면 옆자리) |
| `lease_rejected` | 노크 자리에서 튕김 + 노란 말풍선 "423 · 잠겨 있음" → 자기 문 쪽 "문 밖" 자리로 물러나 ⧗. 줄을 세우지 않는다(노란 점선은 대기 구역 표시일 뿐 순서가 아님) |
| `lock_released` | 자물쇠 제거 |
| `custom:holder_left` | 보유자가 release 없이 자기 문으로 걸어 나감 + "A 이탈 · release 없음 · 잠금은 남음" 팝업. 자물쇠는 남는다 |
| `custom:holder_paused` | 보유자가 제자리에서 회색(mist) 실루엣으로 굳고 ■ 감정 표시 + "A 멈춤 (GC·네트워크 단절) · 잠금은 남음" 팝업. 사본(옛 fence)은 든 채. 늦은 저장(`arrived`)에서 색이 돌아오고 409 lease_lost를 받는다 |
| `lease_expired` | 자물쇠가 회색 + 빨간 사선, DB 표지에 `만료` |
| `responded` | 출입구로 퇴장 |

- **시간 표시**: 무대 시간 40ms = 실제 1ms다. 속도 이름은 `아주 느리게(1/400) · 느리게(1/160) · 보통(1/80) · 빠르게(1/40)`이고 기본은 느리게다. 화면에는 늘 "실제의 1/N 속도"와 실제 ms를 함께 적고, 타임라인 시간은 실제 ms로 적는다. 편집 구간(사람 시간)은 실험실 think time을 압축해 그린 것이라고 밝힌다.

## 6. Grafana 임베드를 이 톤에 맞추기 (화면 5)

Grafana 패널 내부는 Grafana의 렌더러가 그린다. 그래서 픽셀 폰트나 도트 스타일을 패널 **안에** 억지로 넣지 않는다. 바깥 틀과 색을 맞추는 것으로 충분하다.

1. **프레임으로 감싸기**: iframe을 이 문서의 패널 컴포넌트(2px `--edge` 테두리, 계단 모서리, `.panel__h` 머리줄) 안에 넣는다. 머리줄에는 대시보드 이름, `runId`, 시간 범위(= 실행 구간), "Grafana에서 열기" 링크를 둔다. 틀은 픽셀 스타일, 그래프 내부는 Grafana 그대로다.
2. **테마 맞추기**: 임베드 URL에 `&theme=light` 또는 `&theme=dark`를 붙여 앱 테마와 맞추고, 테마가 바뀌면 `src`를 다시 설정한다. kiosk(`&kiosk`)나 `/d-solo/...` 패널 URL을 써서 Grafana 자체 크롬을 숨긴다(DESIGN §9.5).
3. **시리즈 색 고정**: 프로비저닝하는 대시보드 JSON에서 field override로 색을 고정한다. 성공/커밋=`#1F7F45`, 대기·큐 길이=`#E2AE24`, 실패·위반=`#CC3B34`, 재시도=`#EB7A2C`, 정보·처리량=`#2F6BCB`, 기타 시리즈=`#4B5262`/`#94704F`. 같은 의미는 화면과 Grafana에서 같은 색이 된다.
4. **정합성 패널 먼저**: 실행 개요 대시보드 맨 위의 정합성 Stat 패널은 위반 0이면 초록, 1 이상이면 빨강으로 칠한다(threshold). Stat 값 옆에는 단위와 설명 텍스트를 함께 둔다.
5. **배경 맞추기**: Grafana 패널 투명 배경(`transparent: true`)을 쓰고 iframe 바탕은 `--panel`과 같게 둔다.
6. **하지 않는 것**: Grafana 플러그인·CSS 해킹으로 폰트를 바꾸지 않는다(업데이트 때마다 깨진다). iframe 위에 CRT 효과 같은 필터를 덮지 않는다(읽기 어렵다).
7. 확인 필요: 임베드하려면 `allow_embedding = true`, 익명 뷰어 권한, `X-Frame-Options` 설정이 필요하다. 구현할 때 Grafana 공식 문서로 확정한다.

## 7. 접근성

- 상태는 색 + 아이콘 + 글자 세 겹으로 표시한다. 타임라인의 대기 구간은 빗금을 넣어 색각 이상에서도 구분되게 한다.
- 결과 카드에는 `aria-live="polite"`를 준다. HUD 정합성 배지에는 `role="status"`를 준다. 이벤트 로그에는 live를 걸지 않는다(너무 시끄럽다).
- 캔버스에는 `role="img"`와 현재 상황을 담은 `aria-label`을 준다(처리 방식·인원이 바뀌면 갱신). 말풍선 레이어는 `aria-hidden`이다. 같은 정보가 로그·트리에 글자로 있기 때문이다.
- 키보드: 목록은 `?` 오버레이(§4.8). 세그먼트 안에서는 `←→`가 값 이동이다(준비 중 항목은 건너뜀). 포커스 링은 2px `--info`다.
- 용어 툴팁(`.term`, 점선 밑줄, `tabindex=0`)은 마우스 올림과 키보드 포커스 둘 다로 열린다. identity map, flush, 0행 갱신, lockVersion, lease, 409, 423, READ COMMITTED, WHERE 재평가, 행 락, fencing, nativeUpdate, Retry-After.
- 자동 멈춤 설명의 `계속` 버튼은 실제 버튼이다(무대 위 레이어 중 이것만 포인터를 받는다).
- `prefers-reduced-motion`이면 깜박임·밀려들기 애니메이션을 끈다. 무대 이동은 정보이므로 유지한다. 대신 기본 속도가 느리고(느리게 = 1/160), 자동 멈춤과 단계 이동으로 움직임 없이도 기록을 따라갈 수 있다.

## 8. 금지 사항

- 실존 게임기·게임의 **로고, 상표, 기기 이름, 버튼 배열이나 본체 모양 흉내, 캐릭터, 스프라이트, 효과음**을 쓰지 않는다. "옛날 휴대용 게임 화면 같은 느낌"은 도트·팔레트·폰트로만 낸다.
- 외부 이미지·스프라이트 에셋을 쓰지 않는다. 그래픽은 모두 코드(CSS/SVG/캔버스)로 그린다.
- 폰트 외의 외부 리소스를 쓰지 않는다. 외부 스크립트도 쓰지 않는다.
- 팔레트 밖의 색을 임의로 추가하지 않는다. 필요하면 이 문서 §1부터 고친다.
- 상태 색의 의미를 바꾸지 않는다(예: 노랑을 "절충"으로 쓰기, 초록을 장식으로 쓰기).
- 픽셀 폰트를 설계 크기의 정수배가 아닌 크기로 쓰지 않는다. 무대를 정수배가 아닌 배율로 늘리지 않는다.
- CRT 주사선, 색수차, 흔들림 같은 "레트로 효과"를 정보 위에 덮지 않는다.
- 처리량을 정합성보다 먼저, 또는 더 크게 보여 주지 않는다. 운영 용량을 주장하는 문구를 쓰지 않는다(DESIGN §3.1).
- 재생 속도를 실제 시간처럼 보이게 쓰지 않는다. 무대 시간 옆에는 늘 실제 ms와 배율을 함께 적는다.

## 9. 시안에서 아직 안 한 것

- 코드 패널의 이벤트 매핑은 phase 단위 수작업 표다. 실제 구현에서는 이벤트의 codeRef로 자동 연결해야 한다.
- 필드 병합(field-merge)은 세그먼트에 `준비 중`으로만 있다(장면·코드 없음).
- 편집 잠금에서 TTL보다 긴 편집(30초·5분)은 잠금 연장(heartbeat)을 가정하고 결과 숫자만 바꾼다. 연장 코드는 없다.
- 컨트롤러(version 누락 428 · 타입 오류 400 검증과 number 변환, 423의 Retry-After 헤더 설정)는 코드 주석으로만 적었다.
- 서버 인스턴스 kill 장면(잠금은 DB 칼럼이라 영향 없음을 보이는 짧은 확인)은 넣지 않았다. 편집 잠금의 보유자 종료는 클라이언트 이탈·멈춤 두 장면으로만 보인다(§4.10).
- 실제 WebSocket 이벤트 연결. 실행 중 라이브 보기(기록이 쌓이는 동안 뒤따라 재생)와 재생 버퍼(0.5~1초) 표시, actor 클릭 → 워터폴(화면 4 전체판).
- 다른 장면 타입(queue-at-counter, conveyor 등)의 스프라이트.
- 화면 1·2·5~10의 실제 레이아웃(시안은 썸네일 3개만).
- 실제 구현에서는 PixiJS(DESIGN §10.3)로 옮긴다. 이때도 이 문서의 정수 배율, 비트맵 정의, HTML 글자 레이어 규칙을 그대로 쓴다(PixiJS: `TextureStyle.defaultOptions.scaleMode = 'nearest'`, 정수 배율로 resize — API 이름은 구현 시 확인).
