# nestjs-under-load

동시 요청·대량 쓰기·장애 상황에서 서버와 DB 안에서 실제로 무슨 일이 일어나는지 눈으로 보는 로컬 실험실.

같은 API에 처리 방식만 바꿔 가며 같은 조건에서 돌리고, 정합성(잃어버린 수정, 중복, 음수 재고 등)과 지연·처리량을 나란히 비교한다. 부하는 k6로 넣고, 결과는 Grafana와 실험 화면에서 본다.

**코드는 전부 AI가 작성한다.** 사용자는 IDE형 학습 화면 "코드 실험실"에서 부하·상황별로 어떤 코드가 들어가야 하고 왜 그런지를 학습한다(`packs/**/learn.yaml`, 예상과 실측을 구분 표시). 실험 노트(예측 → 실측 → 원인)는 사용자의 학습 기록이다.

> NestJS + MikroORM으로 구현하지만, 다루는 문제(락, 격리 수준, 커넥션 풀, 대량 쓰기, 캐시, 과부하, 비동기 일관성)는 DB·인프라 공통이다.

## 상태

**0단계 진행 중.** 설계 문서와 G02 팩(`packs/generic/g02-stock-decrement`), 실험 대상 앱(`apps/app`), 최소 실행기(`scripts/run.mjs`)가 있다.

- [설계서](docs/DESIGN.md) — 구조, 측정 원칙, 관측, 화면(코드 실험실 포함), 학습 데이터 규약
- [시나리오 카탈로그](docs/SCENARIOS.md) — 범용 팩 + 세무 팩(상태 전이·승인 규칙이 많은 업무 도메인 예시)
- [로드맵](docs/ROADMAP.md) — 단계별 완료 기준
- [실험 노트 양식](docs/EXPERIMENT_TEMPLATE.md)

**최소 사양:** Docker에 8 vCPU / 10GB 이상 권장. 부족하면 `minimal` 프로필(app×2, nginx, postgres, k6, prometheus, grafana)로 돌리고, 결과에 `profile: minimal`이 기록된다. Apple Silicon은 P/E 코어 편차가, Linux 네이티브 Docker는 cpuset 의미 차이가 있어 결과에 함께 남긴다.

## 원칙

- **코드는 AI가, 학습은 사람이.** 경계는 DESIGN §5.4 표로 공개한다.
- **정합성이 먼저다.** 빠르지만 틀린 결과는 순위에서 뺀다.
- **상대 비교만 말한다.** 로컬 단일 머신의 절대 수치는 운영 용량이 아니다. 결과에는 측정 조건을 함께 적는다.
- **로컬 전용.** 사용자가 편집한 부하 스크립트를 실행하는 구조라서 외부에 노출하지 않는다.
